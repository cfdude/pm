# gh-cfdude-pm-224 — the test suite stops leaking temp directories

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. TDD per task; the RED lands
> in the same commit as its GREEN (the pre-commit hook runs the whole assertion half).

**Goal:** a suite run leaves no `pm-*` directory behind in the OS temp dir, and a guard fails when a
fixture starts leaking again.

**Architecture:** reuse 0.49.0's ONE removal mechanism, `scripts/test/fixtures/temp-dir.mjs`
(`removeAtExit` / `removeTempDir` / `scheduledForRemoval`). Every `mkdtempSync` in `scripts/test` either
schedules its directory with `removeAtExit(...)` or removes it itself in a `finally`. No second mechanism.

epic's watermark — unchanged).

## Guard — two files, one id (`temp-dir-cleanup`)

- **functional/temp-dir-cleanup.test.mjs** — observes BYTES LEFT ON DISK AFTER A PROCESS EXITS, which only
  a spawned run can show, and the assertion half may not spawn: functional. It builds a hermetic root,
  runs nested `node --test` processes with `TMPDIR` pointed inside it — a generated PROBE file calling
  `tmpRepo`, `fixtureCache`, `fixturePluginRoot`, `addHierarchyWorktree` and `buildFixture`, plus a list
  of real site files — and asserts: each child exited 0 with `pass > 0`; every path the probe recorded
  lay under the hermetic TMPDIR and existed while it ran (non-vacuity); zero `pm-*` entries remain.
- **assert/temp-dir-cleanup.test.mjs** (the twin; file rung — it reads source bytes and makes dirs):
  (a) each helper's directory is in `scheduledForRemoval()`; (b) an enrolment sweep: every
  `mkdtempSync(` call in `scripts/test` (comments stripped) is `removeAtExit(`-wrapped on its line or is
  named in a KNOWN table with how it is removed — so a NEW unscheduled site fails per commit, which the
  triggered functional guard alone would not catch. conductor-33 sits in the table as the named tail.

## Required items

### Item 1 — call-site sweep

- **The rule:** every temp directory the test tree makes is removed. **Callers, derived** with
  `rg -n 'mkdtempSync\(' scripts/test` minus comment lines: 30 call sites. 20 are wrapped in
  `removeAtExit(` on their line; the other 10 are exactly the twin's `KNOWN` table — 9 removed their own
  way (`finally`, the shim's exit listener, `fixture-snapshot`'s `after()` hook) and 1 is the tail,
  `assert/conductor-33.test.mjs:121` (`scratchDir`, `pm-seg*`), which another agent owns in 0.50.0.
  The twin's enrolment test holds this per commit, so the list cannot go stale silently.
- **A site that is not an `mkdtempSync`:** `git-gateway-repo.mjs`'s `root + "-wt"` linked worktree —
  found by the functional probe, not by the scan — is scheduled too. `helpers.mjs`
  `observationRepo({ clone })` removes a `tmpRepo()` path and clones into it; the scheduled path is the
  same, so it is removed. The engine (`scripts/lib`, `conductor.mjs`) creates no temp directory
  (`rg -n 'mkdtemp|tmpdir\(' scripts/lib scripts/conductor.mjs`: comment only).
- **Three sites that removed inline, not in a `finally`** (`drift-script` ×2, `emitted-invocations:3052`)
  leaked only when their own assertion failed; they are now scheduled as well.
- **Data reference:** `temp-dir.mjs`'s `scheduled` Set. Written by `removeAtExit()`; read by the single
  `exit` listener and by `scheduledForRemoval()`; never removed from.
- **Inverse:** unscheduling a directory is NOT shipped. Justified: no caller keeps a fixture past the
  process that made it, and a fixture that must survive the process would be a new requirement. The
  other inverse is the KNOWN table's: an entry whose site is gone or has since been scheduled fails
  the twin's "every KNOWN entry still names a live, unscheduled site" test. The tail entry is exempt
  from that, so closing it is the owner's step: delete the entry when `scratchDir()` is scheduled.

### Item 7 — route what the work taught

- **Tooling friction (filed):** https://github.com/cfdude/pm/issues/227. Drift check 3 forced a no-op

- **Practice (not registered, not new):** "count the leftovers in a hermetic TMPDIR" is now a
  functional guard in the tree, so it is enforced where it binds.
- **Process lesson:** none new. The existing `filter-at-read-time-not-at-capture-time` lesson fired
