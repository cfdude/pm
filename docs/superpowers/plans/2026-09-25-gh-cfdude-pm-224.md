## Guard — two files, one id (`temp-dir-cleanup`)

- **functional/temp-dir-cleanup.test.mjs** — observes BYTES LEFT ON DISK AFTER A PROCESS EXITS, which only
  a spawned run can show, and the assertion half may not spawn: functional. It builds a hermetic root,
  runs nested `node --test` processes with `TMPDIR` pointed inside it — a generated PROBE file calling
  `tmpRepo`, `fixtureCache`, `fixturePluginRoot`, `addHierarchyWorktree` and `buildFixture`, plus a list
  of real site files — and asserts: each child exited 0 with `pass > 0`; every path the probe recorded
  lay under the hermetic TMPDIR and existed while it ran (non-vacuity); zero `pm-*` entries remain.
- **assert/temp-dir-cleanup.test.mjs** (the twin; file rung — it reads source bytes and makes dirs):
  (a) each helper's directory is in `scheduledForRemoval()`; (b) an enrolment sweep: every
  `mkdtempSync(` call in `scripts/test` (comments stripped) is `removeAtExit(`-wrapped on its line or is
  named in a KNOWN table with how it is removed — so a NEW unscheduled site fails per commit, which the
  triggered functional guard alone would not catch. conductor-33 sits in the table as the named tail.
