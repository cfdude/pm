## Inverses (named and justified)

- `sync --dry-run`: a read, nothing to unwrite.
- `sync --only`: registers epics the same way a full sync does; undone by `remove-epic` (existing, writes the sync-ignore tombstone). No new inverse.
- `--spec-deltas-waived`: `--clear spec-deltas-waived` (generic nullable clear, announced, tested).
- `earliestIntroduction` / `--full-history`: a read; the stamped date's inverse is the existing `--clear created-at`.
- rules paragraph: emitted text, no state.
- verb-registration guard: a test, no state.

## Decisions

- #1 smallest design: two flags, `--dry-run` (stdout report, exit 0) and repeatable `--only <id>` matching change, plan or stripped archive ids. A typo is refused before the write (on a dry run too) rather than reading as a clean selective sync. A selective run leaves `archiveBackfilledAt` unstamped.
- #2 chose the LOUD GUARD over deriving the tables from one registry: the tables live in `conductor.mjs` (a literal dispatch object and `USAGE` string) and in two test files that cannot import from a registry without restructuring the engine entry point.
- #3 value is the reason (string), not a `{reason, at}` object: the epic's `touchedAt` already dates the write. The `integrity` finding does not print the flag: that harness (`emitted-invocations.test.mjs`) builds a fixture per printed alternative and would need a new waiver alternative and a re-check, which was not budgeted here (UNVERIFIED that it would fail); the flag is documented in `commands/epic.md` and `commands/status.md`.
- #4 cause attributed to git's default history simplification (and traversal-order-not-date selection); the real-git fixture reproduces the pruning and asserts it first.
- sync's `VERB_EFFECTS` row carries `dryRunFlag: "--dry-run"` and conductor.mjs skips the detached-tree discarded-write warning for it (purge-logs --dry-run has the same latent false warning; left alone).
- #5 is PARTIAL against its grooming note: the two absorbed obligations (Orient reads the spec inventory; autonomy grant propose/apply boundary) were not built. Only the planning-completeness rule was.
- #5 placed in the existing refresh-gate section (the moment an epic becomes the work), one paragraph, not a ninth gate-procedure item (that would have to be mirrored on the skill and command docs).
