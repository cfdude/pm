# Theme B batch B1 (pm 0.51.0): update-epic validation, attribution and gate staleness

Six superpowers-lane epics, one branch, one full run. Issues: cfdude/pm #216, #237, #233, #232, #198, #205.

## Decisions

- **216** The staleness rule already reads the SET (`commitsNotReachedBy` over every attributed entry), so
  option 1 of the issue is already true and nothing is reordered. What broke is every POSITION-reader:
  the stale-Gate-2 remedy (`--head-sha <the last attributed commit>`) and integrity's bookkeeping arm
  ("the merge commit" = last array element). Fix those, document the set semantics.
- **237** A duplicate is a no-op (exit 0, stderr line, nothing written), not a refusal: the observed case is
  a retry after a hook failure, and a nonzero exit turns an idempotent retry into an error. Dedupes across
  the existing array and within one call. This is consistent with 216 only because 216 removes the
  "re-attribute the head to repair the order" workaround.
- **233** Refuse `--no-deferrals` with `--deferral` or `--declined-deferral`, before any write. The
  "section `none`" aside in the issue is declined: the section is free text by design.
- **232** Refuse a trailing-slash value and a path that EXISTS and is not a regular file. A path that does not
  exist is still accepted (a plan may be attached before it is written; an archived-and-moved plan is the
  deliberate dangling case `epicProgress()` reports).
- **198** Digests ride beside the unchanged `artifacts` path list as `artifactDigests: [{path, sha256}]`
  (Gate 1 only). Located live, then through `archivedChangeDir` (the one archive resolver) so the archive
  move is not staleness. No digests = unverifiable, never stale. Rendering signal only; never read by the
  archive gate.
- **205** The answer is an ordering rule plus a guard, not a new holder: commit lifecycle work before
  recording Gate 2, and do not attribute it where you cannot; `--attribute-commit` now says when it turned a
  passing Gate 2 from fresh to stale and names `--withdraw-commit`. The harm that remains: such a commit is
  recorded nowhere the engine reads. A `--lifecycle` holder was weighed and rejected as a new array with its
  own withdraw path, integrity enumeration, read-back and cross-array duplicate rule.
