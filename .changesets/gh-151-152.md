# gh-151 / gh-152 — a rule and a guarantee that each stopped where the engine stopped

## Added — #151: `push-detour` and `pop-detour`

The substantial detour's PUSH was a **documented hand-edit of `.conductor/state.json`**
(`commands/detour.md` step 2). The state of record's most consequential transition — parking one
piece of work to build another — was performed by the one mechanism this project tells every
agent never to use, and none of the engine's guarantees applied to it: no validation that either
epic exists or is live, no non-empty reason, no deliberate `reconcileOnResume`, no write-conflict
guard, no read-back verification, no record that the transition happened at all.

```bash
push-detour <parent-epic-id> --detour <detour-epic-id> --reason "<why>" (--reconcile | --no-reconcile)
pop-detour [<paused-epic-id>]
```

`push-detour` does the hand-edit's work plus what only the engine can: it refuses an unknown or
archived epic on either side, refuses the two being the same, refuses an epic already on the
stack, requires a non-empty reason (through the shared `REASON_REQUIRES` phrase `update-epic
--reason` and `release --reason` already use), writes the frame, records both protocol links
(detour `resolves-blocker-for` parent; parent `may-invalidate` detour), activates the detour, and
emits the Honcho line — all in ONE `saveState`, so it inherits the write-conflict guard and
0.32.0's read-back verification.

**The reconcile decision must be said.** Exactly one of `--reconcile` / `--no-reconcile` is
required and there is no default, on the precedent `--no-deferrals` set: an absence must be
*claimed*, not arrived at by forgetting. A default-on reading is defensible on safety grounds,
but `reconcileOnResume` is the one flag whose documented property is that it must survive until
reconciliation completes, and a default makes an absent decision indistinguishable from a
considered one. A mistaken `--no-reconcile` is attributable; a forgotten default is not.

### POP needed it too — the issue flags this as worth checking, and the answer is yes

`/pm:resume` runs the engine at step 3 (`record-reconcile`) and step 4 (`honcho-memory pop`), and
**neither removes a frame**: `record-reconcile` writes a verdict onto a link and clears
`reconcileNeeded`. `rg detourStack scripts/` finds only readers. The pop itself was
`commands/resume.md` step 2's hand-edit, so fixing PUSH alone would have left the identical
sibling site untouched.

`pop-detour` removes the top frame, resumes the epic, and writes `reconcileNeeded` **in the same
write** — load-bearing, because `reconcileArchived()` clears that flag for any epic with no live
frame that is not `state.active`, and POP removes the frame *before* reconciliation runs. A pop
that set the active pointer in a second write, or rendered in between, would erase the obligation
it had just created. It warns rather than refuses when the detour epic is not yet archived:
refusing would strand a stack whose detour was removed or renamed with no CLI way out, which
re-creates the hand-edit the verb exists to remove. It emits the POP Honcho line only when
nothing needs reconciling — `resumed X, reconciled vs Y` is not true until the verdict exists.

**#94's gate becomes buildable.** Its deferral disclosure now fires at the moment of the deferral
rather than one step after it. The gate is still not built, and the reason narrows to the two
that were always about evidence: a detour is not a failure, and no threshold is defensible on
this repository's record. `honcho-memory push` keeps the disclosure for a pivot recorded after
the fact.

`commands/detour.md`, `commands/resume.md`, `skills/conductor/SKILL.md`, the README and the
**emitted rules block** all stop instructing a hand-edit. That half matters as much as the verb:
a verb nobody is told to use changes nothing.

## Fixed — #152: the flag-value rule stopped at the registry

0.34.0 made a valueless value-bearing flag a refusal across the six write surfaces `EPIC_FLAGS`
declares. `valueBearingFlagsFor()` returned `[]` for every other command, so the guard silently
no-op'd on a dozen more verbs — and two of them (`triage --limit`, `verify-specs --root`) had
each **invented the same answer by hand, independently**. That is the tell the rule was bound to
a list rather than to the function it governs
(`docs/lessons/bind-rules-to-functions-not-enumerations.md`).

**Shape chosen: one declaration site, two scoped tables, no rename.** `EPIC_FLAGS` keeps its
name; a sibling `VERB_FLAGS` declares the flags of every other dispatched verb, and
`valueBearingFlagsFor()` reads the **union**, so every existing call site was covered without
changing its code. The rename to `FLAGS` was declined: the name is load-bearing in all four of
its projections — `epicFlagsFor()` builds four commands' allowlists, `epicBatchKeys()` builds
`add-many`'s accepted batch keys, `epicFlagCommands()` and `repeatableEpicFlags()` feed the
sweep and the parser — and `changelog --since` is not an epic flag under any of them. Per-verb
declarations were declined for the opposite reason: the surface list has to be derivable
mechanically in **one** place, and declarations living beside each verb make the derivation walk
a dozen modules to find what is missing. Where the two tables need the same words they share a
constant (`REASON_REQUIRES`), not a row.

Rows are **scoped**, and `--remove` is why that matters: a value-bearing match string on
`set-lane-routing`, a boolean on `set-tracker`. One global row for the spelling would have to
pick one reading, and either choice is wrong on one of the two verbs.

`set-autonomy --level` was the sharpest instance and is now a refusal: it used to write an
autonomy block and exit 0 with the level silently absent, on the verb whose entire purpose is
recording how much trust an epic has.

### The surface list is derived from the dispatch table, not from the registry

conductor-30 derives its sweep from `epicFlagCommands()`, so a verb *with* flags and *no* row is
invisible to it — which is exactly how a dozen verbs came to sit outside the rule. The new check
reads `conductor.mjs`'s own dispatch object and asserts every dispatched verb is claimed by
**exactly one** of the two flag tables or an explicit `FLAGLESS_VERBS` list, so "this verb takes
no flags" and "nobody declared this verb" cannot look the same. It found one undeclared flag
immediately: `render --diff-summary`.

`repeatableFlags()` also stops carrying a hand-written six-name list beside a registry that can
declare them; it is now a projection of both tables.

### Behaviour change — what breaks, and for whom

Every spelling below used to exit 0 having written nothing, or something unusable:

| Was | Now |
|---|---|
| `set-autonomy --level` with no value | refused; no autonomy block written |
| `set-lane-routing --add` / `--remove` with no value | refused (they arrived as `[true]` and matched nothing) |
| `set-tracker --instance` / `--mechanism` / `--repo` / `--project` / `--role` / `--system` / `--direction` / `--intent` with no value | refused |
| `record-tracker-refresh --summary`, `record-reconcile --amendments` with no value | refused (recorded as if never passed) |
| `changelog --since`, `plan-hierarchy --parent`, `add-many --from`, `set-review-mode --mode`, `rules --epic` with no value | refused |
| `write-rules --platform` / `rules-target --platform` with no value | refused (it silently fell back to the recorded platform while looking answered) |
| any of the above with a **blank** value (`--mode "   "`) | refused |

`triage --limit` and `verify-specs --root` keep their own stricter checks — the shared rule does
not subsume them (`--limit abc` carries a value and is still not a positive integer) — but the
refusal **text** for a valueless `--limit` changes from triage's bespoke wording to
`conductor: --limit requires a positive integer`. `verify-specs --headers` stays a boolean arm
that refuses a value; the valueless marker exempts it from the rule and did not make it
permissive.

No migration for either half. #151 does not change the detour-frame shape, so frames written by
hand load unchanged; #152 is a parse-time refusal and changes no state shape.
