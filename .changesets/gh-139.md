- **The command docs no longer resolve the engine out of the project directory (#139).**
  Fourteen shipped instruction files — thirteen `commands/*.md` and `skills/conductor/SKILL.md` —
  opened their engine-resolution snippet with
  `ENGINE="${CLAUDE_PROJECT_DIR:+$CLAUDE_PROJECT_DIR/scripts/conductor.mjs}"`, tried FIRST and
  tested only with `-f`. Any project carrying a file at `scripts/conductor.mjs` therefore had that
  file executed by `node` the moment a user typed a `/pm:*` command — no check that the project is
  pm, and nothing there the project could not itself write. Lower severity than #134's hole (this
  needs a typed slash command AND a failed plugin-cache lookup; #134's ran on four hooks with no
  user action), but the same shape.

  **The arm was deleted, not gated.** It was added in 9e83963 for exactly one audience —
  *"when the repo being worked on IS the pm plugin source (self-hosting)"* — and #134 now serves
  that audience through something the project cannot write: `PM_ENGINE_DELEGATION=<absolute path>`,
  honoured at the top of `conductor.mjs` before dispatch, so one handoff covers all 19 entry points
  including these commands. No ordinary user ever benefits from resolving pm's engine out of their
  own repo; a contributor already has a better mechanism. A gate here would have been a switch
  with nobody to operate it (`docs/lessons/who-can-operate-the-switch.md`).

  Resolution is now `$CLAUDE_PLUGIN_ROOT`, then the newest installed copy under
  `~/.claude/plugins/cache/`. The residual edge — `$CLAUDE_PLUGIN_ROOT` empty *and* the cache glob
  missing, e.g. a plugin installed from a local marketplace path — is unchanged in kind by this
  release and its answer is the one contributors already use: run
  `node scripts/conductor.mjs <verb>` from the checkout.

  `scripts/test/engine-resolution.test.mjs` is the standing gate. It walks **every** shipped
  instruction surface — `commands/`, `skills/`, `agents/`, `hooks/`, `.claude-plugin/`, not only
  the two directories the issue named — and fails on two resolution shapes: the
  `${CLAUDE_PROJECT_DIR:+…}` expansion that shipped, and a direct
  `$CLAUDE_PROJECT_DIR/scripts/conductor.mjs` however quoted or braced. Both are mutation-proven.
  It is a guard against the pattern that actually appeared, not a proof of impossibility — an
  indirection through another variable, or a `cd` plus a relative path, would still pass it.
  Legitimate prose mentions of the variable (banner suppression, the worktree caveat) are
  deliberately not matched, and a fixture test proves both banned shapes are detected so the
  empty-result assertion cannot be vacuous.

  Not collapsed: the snippet still lives in fourteen hand-maintained copies. Claude Code has no
  include mechanism for command docs, and the copies differ legitimately in shape (twelve inline
  one-liners with per-command verbs, two fenced blocks) and in indentation, so a byte-identity
  check would be a normalization exercise dressed up as a single source of truth. The guard above
  fails CI on the form that shipped and on its direct hand-rolled variant, which is the
  property that mattered.
