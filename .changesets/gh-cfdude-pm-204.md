* **New read-only `list` verb: the engine now answers "which epics exist" (#204).** Intake, the tracker-sync dedup and a disposition's `--deferral "<epicId>:<section>"` all need the set of existing epics, and the engine had no verb for it: agents were told to run a `epic list` that did not exist and fell back to reading `.conductor/state.json`, the file the rules forbid hand-editing, guessing its shape. `list [--status <status>] [--lane <lane>] [--linked-to <epicId>] [--json]` filters the record and prints one line per epic, or `{count, epics}` with `--json`. `--linked-to` is incoming (the epics carrying a link to that id), which is the deferral-list question. It is read-only, and its command doc is `commands/list.md`. The optional `add-epic` warning for a title equal to its id was not done.
