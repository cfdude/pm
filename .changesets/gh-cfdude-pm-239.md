* **`log-detour` can name its commit, and a wrong MINIMAL row can be retracted (#239).** In a consumer repo a commit for a minimal detour was blocked by a format hook, `log-detour "<what>"` ran in the same shell step and recorded the description against HEAD, which was still the PREVIOUS commit (already logged as its own detour), and `retract-detour` refused the wrong row because it is MINIMAL. The row was permanent. Now `log-detour --sha <sha> "<what>"` records the declaration against that commit (refused, writing nothing, when the sha names no commit here), and when HEAD already carries a visible MINIMAL row and no `--sha` was given, it says so after writing and names the repair. The inverse is `retract-detour <sha> --minimal "<exact description>" --reason "<why>"`: it appends a `RETRACTED-MINIMAL` row naming the one target's timestamp, hides only that row from `PROJECT.md`, keeps it in `.conductor/detours.log`, and leaves the commit's AUTO-DETOUR and DETOUR-COMMIT rows alone (a sha-keyed `RETRACTED` row would hide those too). An engine older than this one shows the `RETRACTED-MINIMAL` row itself in `PROJECT.md`. `log-detour` was a flagless verb and now declares `--sha`, so its unknown-flag refusal reads `it accepts: --sha, --force`.
