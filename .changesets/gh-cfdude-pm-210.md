* **`upgrade` now lists the opt-ins this repo has never adopted, on every run (#210).** The changelog delta only names what a release added, so an opt-in skipped at an earlier release was invisible forever: a 175-epic repo upgraded at every release from 0.16 to 0.45 still had `laneRouting` unset, and every `suggest-lane` and `triage` returned null. After the delta, `upgrade` prints one `opt-ins` summary line of what is adopted and one `NOT SET` line per opt-in that is not, each naming the command that adopts it (`set-review-mode`, `set-lane-routing`, `set-activity-log`, `set-tracker`, `claim`). The list is read from a registry in `scripts/lib/opt-ins.mjs`, so a new opt-in is one row. It is a read of `state.json` and enables nothing. `commands/upgrade.md` step 2 tells the agent to judge each line against the repo.
