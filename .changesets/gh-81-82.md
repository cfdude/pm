# gh#81 + gh#82 — a working tree that settles, and a root that says which repo it is

## Fixed

- **`PROJECT.md` no longer loops (#81).** Committing the conductor's own re-render used to append
  a `DETOUR-COMMIT` row for that commit, which changed PROJECT.md's "Recent detours" table, which
  re-rendered PROJECT.md, which dirtied the tree again — forever. A commit touching ONLY pm's own
  generated output (`state.json`, `PROJECT.md`, `render-stamp.json`, `commit-watch.json`) is now
  recognised as bookkeeping on the `DETOUR-COMMIT` branch, exactly as it always was on the
  `AUTO-DETOUR` branch. `git status` reaches clean in one extra commit instead of never.
- **The detour log is idempotent on SHA (#81).** `DETOUR-COMMIT` and `AUTO-DETOUR` rows are keyed
  on the commit they describe, so re-firing the hook for a commit already in the trail writes
  nothing. `MINIMAL` rows are exempt — they record what the agent DECLARED, not what git observed,
  so two minimal detours between one pair of commits are two real events. A `-` sha ("no git",
  "no commits yet") is a cannot-answer, never an identity, and never collapses rows.
- **The render timestamp was already handled and now has a regression test (#81).** `render()`
  skips the rewrite when the only difference is `Last rendered:`, so the stamp alone can never
  dirty the file — and it still MOVES whenever real content changes, which is the half that keeps
  the file honest. Both directions are now pinned by tests.

## Added

- **A wrong-repo warning for `CLAUDE_PROJECT_DIR` (#82).** When that variable is set, resolves
  (through `realpath`) to a different directory than the cwd, AND the cwd holds a `.conductor/` of
  its own, the engine writes a two-line warning to stderr naming BOTH repositories before it does
  anything. It warns, it does not refuse: cross-repo dispatch is a supported pattern and the
  defect was that a redirect looked identical to a local run in the output, not that it was
  possible. It is not silenced by `PM_QUIET_ENGINE_BANNER`, and not by the presence of
  `CLAUDE_PROJECT_DIR` itself — the condition that redirects every write must not also be the
  condition that makes the engine quietest.

  `ROOT`'s precedence is UNCHANGED. Running the engine from a subdirectory, and pointing it at a
  project from a neutral directory (the test harness, `evals/fixtures.py`, an orchestrator that
  avoids `cd`), are both silent as before.

## Known, not fixed

- `PROJECT.md` is tracked but renders its "Recent detours" table from `.conductor/detours.log`,
  which #106 git-ignored. A fresh clone or worktree therefore renders `_None logged._` and dirties
  the tracked file once. Closing that means deciding whether the table belongs in a tracked
  artifact at all — a design call, not a bug fix.
- `.conductor/render-stamp.json` is engine-written and per-checkout but is not in
  `ensureGitignore()`'s list, so repos that committed it see it change whenever `state.json`'s
  mtime moves. Ignoring it now would not untrack existing copies.
