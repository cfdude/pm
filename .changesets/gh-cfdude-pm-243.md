* **`record-gate-review --gate 1 --verdict pass` now refuses while the change it names fails `openspec validate --strict`.** Two sessions piped `openspec validate <id> --strict | tail -1`, which exits 0 whatever validate returned and keeps only a summary line, and recorded a Gate 1 pass against a spec that did not validate. When an `--artifact` lies inside a live `openspec/changes/<id>/` (and the project has `openspec/config.yaml`), the engine now runs validate itself, unpiped, and reads its exit status. A non-zero exit refuses the verdict, shows validate's output (capped, control characters escaped) and writes nothing. Where validate cannot be answered (no `openspec` on PATH, a timeout, a signal) the check is skipped, never counted as a failure. A Gate 1 `fail`, a Gate 2 verdict and artifacts outside a live change are unchanged. The run is local and read-only (argv is exactly `validate <id> --strict`); the engine still opens no network connection.
