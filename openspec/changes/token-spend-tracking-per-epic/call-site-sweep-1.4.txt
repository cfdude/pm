== 4. Data references ==

  A marker's `epic` holds an epic id.
    written : ingest, into markers.json (raw token, whether valid or not)
    read    : read-time attribution (spend-attribution.mjs attribute())
    removed : `spend --clear --yes` removes markers.json. remove-epic does NOT strip it, and needs no
              path: attribution is computed at READ time, so rows of a removed epic report as reason
              `unknown-epic` and rows.jsonl is never rewritten (pinned by the unit test "A row whose epic
              was removed reports as unknown").
  The timeline's `active` holds an epic id with the same lifecycle: read-time only; a removed epic reads
  as `unknown-epic`. `--clear --timeline --yes` is the only deletion and says what it forgets.

== 5. Inverses (design D8) ==

  set-spend-tracking on        -> set-spend-tracking off                     SHIPPED (off deletes nothing, appends a tracking:off entry)
  ingest (rows, markers, cursor)-> spend --clear --yes                       SHIPPED (plan printed without --yes)
  rows lost / corrupt           -> spend --rebuild --yes                     SHIPPED (keeps rows whose source is gone; refused while off)
  timeline append               -> spend --clear --timeline --yes            SHIPPED (never implicit; says what it forgets)
  rules-block section           -> set-spend-tracking off re-renders without it  SHIPPED

  record-spend (platform-neutral fallback) -> NOT SHIPPED (design D9): no ported platform needs it, and
                                   the rule that stops a manual figure double-counting adapter rows is only
                                   testable against a real second platform. Recorded as a declined deferral
                                   at archive (task 10.2). With no write, there is no inverse owed.
