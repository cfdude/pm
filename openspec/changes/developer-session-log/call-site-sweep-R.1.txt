## Statement: where the capture rule holds, and where it does not (each omission justified)
- Entry points that call ingest: `spend` (spend-command.mjs:118 via ingestForReport), `spend --rebuild`
  (spend-command.mjs:186 passes devLogOptions directly), `spend-guard` (spend-guard-verbs.mjs:243 via
  ingestForReport) and `dev-log` (dev-log-report.mjs:187 via ingestForReport). All four capture while both
  switches are on, because the decision is made in ONE place (devLogOptions, called by ingestForReport and rebuild).
  The test `spend captures, and so does spend-guard` pins the second caller: spend-guard advances the shared
  cursor, so a verb that ingested without capturing would lose those messages permanently.
- `override-spend-guard`, `set-spend-guard` and `set-spend-tracking` do not ingest: no capture owed.
- `spend-analysis` and `decisions` (named in the task text) do not exist on this branch (their changes are not
  built yet); when they land they must call ingestForReport and pass `state`. Flagged for the orchestrator.
- No hook reaches ingest or the file (test: no hook opens or stats devlog.jsonl).
- Single writer of devlog.jsonl: appendDevLog (dev-log-capture.mjs), called from spend-ledger.mjs ingestLocked and
  nowhere else; removeDevLog is the only remover, called from `dev-log --clear` under the ingest lock.

## Inverses (enumerated, each named)
- on <-> off: `set-dev-log on|off`. Off stops capture and keeps the file (test pins it).
- append <-> clear: `dev-log --clear [--yes]` (plan first). Shipped.
- `spend --clear` / `spend --rebuild` do not remove the log. `--clear`: the report degrades to `tokens: not in
  ledger` (design D3), justified; `--rebuild` re-reads every transcript and the append de-duplicates by messageId,
  so it adds nothing twice (test pins it).
- `set-spend-tracking off` stops capture too (devLogOptions needs both switches) and keeps both the file and
  `state.devLog`; `dev-log` then says spend tracking is off.
- `features` snapshot: appended on change only; its inverse is the same `dev-log --clear`.

## Data references
`devlog.jsonl` entries hold `messageId` and `sessionId`, which reference the ledger's rows and a transcript. Writers:
appendDevLog. Readers: `dev-log` (readDevLog). Removers: `dev-log --clear` removes the whole file. A ledger row
removed by `spend --clear` leaves the entry, which the report handles (`tokens: not in ledger`); a pruned
transcript leaves its entries, which stay the only copy of the composition (kept on purpose, like the ledger rows).
